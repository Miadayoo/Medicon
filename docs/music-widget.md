# 音楽ウィジェット

既存の `SocialUi` / `ToastManager` に、Windows のメディアセッションを表示する
`MusicWidget` を追加。新しい UI フレームワークは使わず、ImGui の描画リスト、
DirectX 11/12 の `TextureHost`、`SocialFonts`、`MeshShadowRenderer`、
通知と共通の高さ基準スケール・通知オフセットを再利用する。
ゲーム背景を取り込む汎用ブラーは既存基盤にないため、半透明の暗い塗りと影を使う。
Social サーバーへの接続は音楽表示の前提にならない。

## 動作

- Social → Settings → MUSIC → Show music で表示をON/OFFできる（既定ON）。
  `%APPDATA%/Medicon/social.json` の `music.enabled` に保存し、再起動後も反映する。
  OFF時は通知と同じ退出アニメーションで消え、音声取得も止める。
  OFFで起動した場合は音楽・音声用ワーカーを開始しない。
  ONに戻すと、現在再生中の曲を表示し、手動で選んだサイズを復元する。
- 再生を検出したら、通知位置に 340×100 / 角丸18 のプレイヤーを表示。
  最初の4秒は通常表示、その後は自動で64×64の丸へ縮小する。
  起動時に一時停止中のセッションが残っているだけでは表示しない。
  アート52×52、曲名・アーティストの省略表示、48本の Rainbow 波形。
- 表示を左クリックすると、通常表示と64×64の小さい円形表示を切り替える。
  通知がないときの円形は通知スペースの中央に置く。一度クリックしたら自動切替をやめ、
  次にクリックするまで選んだサイズを固定する。選択は一時停止・再開、曲変更や
  通知の終了後も維持する。クリック途中の反転も現在の形から滑らかにつなぐ。
  操作はカーソルが出ているClickGUI（Insert）・Mediconメニュー・Social画面で受け付ける。
  ウィジェット上のクリックは下の画面へ通さず、枠外で離した場合は切り替えない。
- 通知の実際のレイアウトから左端と中心Yを受け取り、左側14px間隔の
  64×64の円へ350msで変形。36本の放射状波形と、中央に円形のアルバムアートを表示。
  アートは時計回りに40秒で1周する。アートがない場合は音符を使う。
  入場時は通知の最終幅を予約し、カードのSpringの広がりにも追従する。
- サイズ・位置・角丸・内容のクロスフェードは同じ EaseOutCubic で補間。
  途中で方向が変わる場合は現在の補間値から再開する。
- 曲名・アーティスト・再生元が変わったら420msのEaseInOutCubicで曲を切り替える。
  通常表示は画像と曲情報が左へ退出し、次の曲が右から入る。枠と波形は固定する。
  円形表示では、回転を続ける画像を同じ丸い表示範囲の内側で左へ送る。
  画像だけが後から読み込まれた場合はスライドをやり直さない。
  連続スキップでは現在のスライドをつなげてから最新の曲へ切り替える。
  退出する曲の画像は切り替え完了まで保持し、GPU画像のキャッシュは最大2枚とする。
- 通知の退出アニメーションと待機キューがすべて終わるまで Compact を維持。
  通知中のクリックによる展開は受け付けず、終了後に手動で選んだサイズへ戻す。
- 一時停止・停止・終了では非表示にする。別の再生中セッションがあればそちらへ切り替える。
  入退場は既存通知の `ToastManager::morph` と `theme::social::timing` を直接共有する。
  最初は丸が200msで弾んで現れ、160～480msに横へ伸びて角丸が変わり、
  360～560msに文字・アート・波形が出る。丸の拡大と横伸びには通知と同じオーバーシュートがある。
  中身が出るまでの色付きの点も、通知と同じように左の丸い端へ移動する。
  小さい丸での表示開始にも同じ弾みを使う。
  停止時は同じ560msのタイムラインを1.2倍速で逆再生し、
  中身が消える→横幅が丸へ縮む→丸が縮んで消える、の順で約467msかけて退出する。
  退出完了まで最後の曲情報と画像を保持する。
  消える途中で再開した場合はタイムラインの現在位置からそのまま順再生へ戻る。
  再開した場合、まだ手動選択をしていなければ再び4秒の通常表示から始める。
  手動選択済みならそのサイズで再表示する。
- 小さい画面では通知側に音楽用の左余白を確保する。ウィジェットの描画範囲は
  ウィンドウ内へ制限し、ウィンドウ縮小中のアニメーションにも適用する。

## コンポーネント

| ファイル | 役割 |
| --- | --- |
| `src/music/MusicSessionManager.cpp` | 専用MTAワーカーで `RequestAsync`、セッション選択、曲情報・再生状態の監視 |
| `src/music/AlbumArtProvider.*` | `Windows.Storage.Streams` から `BitmapDecoder` で最大192pxのRGBAへ変換、直近の同一画像を再利用 |
| `src/music/AudioVisualizer.cpp` | 専用COMワーカーで既定出力のWASAPI loopbackを取得。既定デバイスの切替・無効化時は再接続 |
| `src/music/AudioSpectrum.cpp` | 1024点Hann窓FFT、50%オーバーラップ、対数周波数48帯域、−65～0dBを0～1へ正規化 |
| `src/gui/MusicWidget.cpp` | 通常／円形描画、同一音声データの共有、Animator・Coordinator、アートのGPUアップロード |

`MediaPropertiesChanged`、`PlaybackInfoChanged`、`CurrentSessionChanged`、
`SessionsChanged` を購読する。Windows の現在セッションが再生中なら最優先、
次に他の再生中セッション、最後に一時停止中セッションを監視する。
再生中のセッションだけ表示を許可する。
一時停止中も購読を続けるので、再生開始のイベントで表示へ切り替わる。
他セッションの再生開始やイベント欠落も1秒間隔の再確認で拾う。
WinRT操作はワーカーでのみ待機し、キャンセル・4秒の上限を持たせる。
停止・切断時にWinRTが成功を返しながら空のオブジェクトを返す場合も確認し、
再生情報が空なら終了扱い、曲情報や画像が空なら再試行または代替表示へ戻す。
アクセス違反はC++の `catch (...)` では捕捉できないため、参照前に確認する。
曲情報や画像の非同期取得後は再生状態を再確認し、取得中の停止を反映する。
失敗時は前の曲情報または「Now playing」／アート用音符へフォールバックする。
終了時はワーカーを停止し、WinRTの購読を所有ワーカーで解除する。

PCM8/16/24/32、float32/64、WAVEFORMATEXTENSIBLE を扱う。
音声取得は約8ms間隔、描画用レベルの更新は最大60Hz。
Attack 35ms / Release 190ms の指数平滑化を使い、120ms以上パケットがなければ
ゼロ入力として減衰させる。音声の保存・送信はしない。
WASAPIは**既定出力デバイス全体の音**なので、ゲーム音・通知音も波形へ入る。
再生アプリが別の出力先を使う場合は、その音を取得できない。

アートは曲情報の更新時に取得し、同じ画像のGPUテクスチャを毎フレーム作り直さない。
丸の中の回転は円形メッシュのUV座標で行い、画像の再生成はしない。
停止時はヒット領域をすぐ解除し、退出アニメーション中も描画を継続してから非表示にする。
一時停止中のアートはキャッシュして再開時に再利用する。
描画デバイスの再生成時にはCPU画像を保持して、新しいホストへアップロードする。
ブラシ・レンダーターゲットの毎フレーム生成は追加していない。

## ビルドと確認

`tools/build.ps1 -Toolchain LLVM`、またはVisual Studio 2022のMSVCでビルドする。
GCC-MinGWはMicrosoftのC++/WinRT投影の対象外として、構成時に明示的に案内する。
Windows SDKのC++/WinRTヘッダーがあれば利用し、ない場合は
SHA-256で固定したMicrosoft公式NuGet `2.0.240405.15` のジェネレーターを使って
WindowsのWinMetadataからビルドディレクトリへ投影を生成する。
任意のSDK投影は `MEDICON_CPPWINRT_INCLUDE_DIR` で指定可能。
起動時のダウンロードや追加ランタイムDLLは不要。

```powershell
./tools/build.ps1 -Toolchain LLVM
./out/build/local/bin/medicon_music_tests.exe
./out/build/local/bin/medicon_music_native_tests.exe
./out/build/local/bin/medicon_music_native_tests.exe --session
./out/build/local/bin/medicon_music_native_tests.exe --loopback
./out/build/local/bin/MediconPreview.exe --scenario music --size 1920x1080 --fixed-dt 0.016666667 --screenshot out/music-screenshots/music.png
```

`--session` はこのテストプロセス専用の非表示ウィンドウでSMTCを作り、
本番の監視クラスで起動時の一時停止では非表示・再生開始で表示・
日本語タイトル・アーティスト・アート・一時停止で非表示・曲変更・再開で再表示・
セッション終了を検証する。既存のプレイヤーの再生状態を変更しない。
一時停止→再開→停止→再開も8回繰り返して確認する。
ほかのアプリが同時に再生していると、そのアプリが優先されテストが失敗する場合がある。
`--loopback` は約2秒の小さな1kHz音（振幅0.005）を出力して、実際のループバックFFTを確認する。
これら2モードはデスクトップや出力デバイスに依存するため通常のCTestには登録せず、
アートのストリームデコードだけ `music_native_art` として登録している。
このテストには再生情報が空・セッション切断・非同期操作が空・画像ストリームが空の
WinRT応答を返すフィクスチャも含む。再生情報が空のケースは修正前に
アクセス違反 `0xc0000005` を再現し、修正後に安全に終了扱いとなることを確認した。

プレビューの `music` は決まったPCMテスト信号を本番FFTへ通し、展開、変形途中、
円形、複数・待機通知、描画デバイス再生成、復元、クリック切替、一時停止、終了の画像を出力する。
クリックの連打・枠外でのリリース・円形の角のヒット判定・通知終了後の手動サイズ維持も確認する。
4秒後の自動縮小・アートの回転速度・クリック後は4秒を過ぎてもサイズ維持・
一時停止時の非表示と再開時の自動／手動モードの復元も検証する。
通知と同じ段階で入退場フレームを保存し、丸の弾み・横伸び・角丸・中身の表示順を比較する。
退出中の再開、セッション削除後も退出が完了するまで描画することも確認する。
曲切り替え中の通常／円形の描画フレーム、連続スキップ、途中での描画デバイス再生成、
SettingsのON/OFFと設定再読み込みも確認する。単体テストではGPU画像の保持・解放、
円形メッシュの頂点とインデックス、停止時の解放、本番SocialServiceでの設定保存と再起動を検証する。
通常の非表示Previewシナリオは、ユーザーのメディア再生状態に依存しない。
