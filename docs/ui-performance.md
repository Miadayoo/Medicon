# GUI / UI の性能改善と検証

2026-10-26。描画品質とアニメーションを維持しながら、毎フレームの計算、GPU の描画範囲、リソース再作成を削減した。

- Edge-lit のガウスぼかしは、隣接する重みを線形サンプリングでまとめ、同じカーネルのテクスチャ参照回数を削減。背景のコピーも HUD 周辺に限定した。
- エフェクト用テクスチャは 64 px 単位で容量を再利用する。必要寸法が容量の半分以下になった場合に縮小し、拡縮後に大きなぼかし領域を保持し続けない。文字メッシュのアップロードはレイヤー単位にまとめた。
- ClickGUI は設定数の重複走査と閉じた設定行の座標生成を省略。ArrayList は文字列を再利用し、入力が変わらないフレームの行照合・並べ替えと、停止中のアニメーション計算を省略した。
- 長いラベルの省略処理を UTF-8 の前方走査に変更。スプラッシュの方向計算と交差計算をリング間で共有し、一時配列のヒープ確保をなくした。
- D3D11 / D3D12 は GUI と HUD の描画内容が両方空の場合、バックエンドの描画処理を省略する。

## Preview の測定結果

NVIDIA GeForce RTX 3060、ドライバー `32.0.16.2101`、Windows、LLVM-MinGW の Release ビルドで測定した。DPI 96、固定 dt `1/60`、各回 60 フレームのウォームアップ後に 600 フレームを記録し、3 回の測定中央値の中央値を比較している。

| 条件 | GPU 時間・変更前 | 変更後 | 減少率 |
|---|---:|---:|---:|
| ClickGUI、1920×1080 | 0.2540 ms | 0.1792 ms | 29.4% |
| HUD、1920×1080 | 0.2570 ms | 0.1669 ms | 35.1% |
| HUD、3840×2160 | 0.4168 ms | 0.2519 ms | 39.6% |

専用フォントを正しく準備したスプラッシュの描画データ生成 CPU 時間は、1920×1080 で 0.1194 ms → 0.0593 ms（50.3% 減）だった。

これは Preview のオフスクリーン描画における UI パスの GPU タイムスタンプ値。P95 はドライバーのスケジューリングやキュー待ちの影響を含み得る。実際の Minecraft の FPS と入力遅延は未測定であり、表の減少率をゲーム全体の FPS 改善率として扱わない。

ログは `out/performance/before/*.log` と `out/performance/after/*.log`。`gpu_timing` は GPU 時間、`cpu_timing` はフォント等の準備・描画データ生成・GPU コマンド送信の CPU 時間を分けて記録する。変更前の測定用 Preview は保存した元の静的ライブラリと元のヘッダーに計測コードをリンクしており、製品コードの ABI が一致する組み合わせを使用した。

ビルド済みの Preview に対し、リポジトリのルートから再実行できる。測定同士を並列実行せず、他の GPU 負荷も避ける。

```powershell
pwsh -File .\tools\measure_ui.ps1 -Preview out/performance/before/MediconPreview-instrumented.exe -Output out/performance/recheck-before -Frames 600 -Runs 3
pwsh -File .\tools\measure_ui.ps1 -Preview out/build/local/bin/MediconPreview.exe -Output out/performance/recheck-after -Frames 600 -Runs 3
```

スクリプトは GUI、設定、HUD、HUD の縮小・拡縮、メニュー、スプラッシュを順番に測定し、各条件の初回に画像も保存する。集計には各条件の 3 ログから `median` を取り出して、その中央値を使う。

## 処理単体の比較

同じ Release 最適化で測定した単体ベンチマーク。上の UI 全体の時間とは測定範囲が異なる。

| 処理 | 変更前 | 変更後 |
|---|---:|---:|
| ArrayList 停止中、5 行 | 0.460 µs / 更新 | 0.117 µs / 更新 |
| ArrayList 停止中、40 行 | 9.20 µs / 更新 | 0.946 µs / 更新 |
| ArrayList 停止中、200 行 | 139.8 µs / 更新 | 4.84 µs / 更新 |
| ラベル省略、32 文字 | 1.8670 µs / 回 | 0.0841 µs / 回 |
| ラベル省略、2048 文字 | 2181.7434 µs / 回 | 2.1774 µs / 回 |

ArrayList は 400 回の準備後、20,000 更新の平均。`out/performance/animator_bench.cpp` と `animator-before.txt` / `animator-after.txt` に条件と結果を保存した。入力の切替、文字幅・配置パラメーター変更、初期化、停止までを含む 2,000 フレームの全行・パルス状態のダイジェストは、変更前後とも `7969774862220593087` で一致した。

ラベルは `FontRole::Label`、既定のフォントサイズ、幅 55 px、`W` の繰り返し、作業用文字列の再利用という条件。10 回の準備後、2,000 回の平均を測定し、出力チェックサムは両版で `32160`。測定コードは `out/performance/font_splash_bench.cpp`。長い文字列ほど大きかった候補文字列の作り直し・再計測を取り除いている。

## 回帰確認

CTest 22 件が成功。GUI の入力、設定、アニメーション、フォント、メニュー、スプラッシュ、D3D11 / D3D12 ホスト、遅延ロードと入力スレッド、HUD の連続拡縮を確認した。フォント省略は CJK、補助平面文字、長文、改行、境界幅、端数サイズを含む 2,734 件を従来相当の参照処理と比較した。

最終ビルドに対して `tools/capture_edgelit.ps1` と `tools/verify_edgelit.ps1` も実行し、23 項目が成功した。空の HUD、影・発光の ON/OFF、文字、輪郭、色、ON/OFF・モード変更アニメーションを実際の描画ピクセルで確認している。

GUI・設定・HUD・メニュー・正しい日本語タイトルのスプラッシュを含む 8 組の比較画像では、RGB 各成分の差は最大 2 / 255 で、それを超える画素はなかった。メニューとスプラッシュは完全一致した。結果は `out/performance/image-comparison.json`。追加した `edgelit_scale_cycle` シナリオによる連続拡縮後の画像も、直接 0.5 倍で描画した画像と完全一致した（`out/performance/scale-cycle-image-comparison.json`）。
