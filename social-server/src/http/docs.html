Medicon Script SDK

C++20 でモジュールを書いて、Medicon にそのまま読み込めます。スクリプトは Windows x64 のネイティブ DLL として動きます。

はじめに

コンパイラは同梱していません。Visual Studio 2022 以降の C++ Build Tools(「C++ によるデスクトップ開発」、MSVC x64、Windows SDK)を入れてください。SDK とサンプルは Medicon に埋め込まれているので、別途ダウンロードは不要です。

  1. Medicon を起動します。%LOCALAPPDATA%\Medicon に Scripts、SDK、Cache\build、Logs が作られます。
  2. Scripts\Hello.cpp を保存します。Script Manager の Create Script からテンプレートで作ることもできます。
  3. 保存から 500 ms 後に自動でビルドされます。
  4. Insert で ClickGUI を開き、Scripts → Script Manager を右クリックします。
  5. ソースパスとハッシュ、診断を確認して Approve & Load を押します。
  6. Scripts に出た名前をクリックすると ON になります。
#include <medicon.hpp>
using namespace medicon;

class Hello : public Module {
    void on_enable() override { chat::print("Hello, Medicon!"); }
};
MEDICON_MODULE(Hello, "my_hello", "My Hello", Category::Utility);

スクリプトは普通のモジュールと同じように扱えます。左クリックで ON/OFF、右クリックで設定、中央クリックでキーバインドです。

ファイル構成

  • Scripts 直下の .cpp は、それぞれが独立したモジュールです。直下の .h / .hpp / .inl は共有できます。
  • Scripts 直下のフォルダは 1 モジュールです。中の .cpp を再帰的にすべてリンクします。
  • MEDICON_MODULE は 1 モジュールにつき 1 回だけ書きます。
  • シンボリックリンクとジャンクションはソースに使えません。
  • SDK フォルダは Medicon が上書きします。編集せず、Scripts にコピーして使ってください。

フォルダには medicon.toml を置けます。

[module]
id = "multi_file"
description = "説明"
required_features = ["render", "local_player"]

id は MEDICON_MODULE の ID と一致させます。required_features は省略でき、指定できるのは chat、render、local_player です。必須機能が足りない DLL は実行前に拒否されます。

エディタは VS Code + clangd が使えます。SDK/compile_commands.json と Scripts/.clangd が自動生成されるので、Scripts フォルダを開くだけで補完が効きます。

Module

Module を継承し、必要なコールバックだけ override します。

コールバック呼ばれるとき
on_enable()OFF → ON のとき。設定の復元後です。listen はここで登録します
on_disable()ON → OFF のとき。この後、イベントとタイマーは自動で解除されます
on_tick()ホストの tick ごと。MCBE の baseTick とは別物です
on_render(RenderContext&)毎フレームの HUD 描画
on_ui(UIContext&)ClickGUI が開いている間の操作できる UI
 
MEDICON_MODULE(Type, "id", "表示名", Category::Visual);
  • ID は 1〜63 バイト、表示名は 1〜95 バイトです。ID は他と重複させず、更新しても変えないでください。
  • Category は Visual、Movement、Player、Utility、Client、Misc です。分類用のメタデータで、ClickGUI の表示先はすべて Scripts です。
SDK はホストが呼ぶコールバックの中でだけ使えます。自作スレッドや DLL 初期化処理からは呼べません。

設定

型は bool、int、float、Color、std::string です。メンバーとして宣言すると ClickGUI に並び、自動で保存されます。

class Example : public Module {
    Setting<bool> greeting = setting<bool>("greeting", "Greeting", true);
    Setting<float> radius = setting<float>("radius", "Radius", 4).range(1, 20, .5F);
    Setting<int> count = setting<int>("count", "Count", 1).range(1, 10);
    Setting<Color> tint = setting<Color>("tint", "Tint", Color{1, .5F, .2F, 1});
    Setting<std::string> label = setting<std::string>("label", "Label", "Medicon");

    void on_render(RenderContext& context) override {
        context.fill_circle(context.center(), radius.get(), tint.get());
    }
};
  • setting と range は Module の構築中だけ使えます。値の取得は .get() です。
  • ID は 1〜63 文字の ASCII 英数字、_、-、. です。
  • モジュール ID と設定 ID を変えなければ、リロードや再起動をまたいで値が残ります。
  • 範囲を変えると既存の値は新しい範囲に収まります。型を変えると初期値に戻ります。

イベント

on_enable で listen<T> を呼んで購読します。OFF になると自動で解除されます。

void on_enable() override {
    listen<GameJoined>([](const GameJoined&) { log::info("Joined a world"); });
    listen<ScreenResized>([](const ScreenResized& e) {
        log::info("Scale: " + std::to_string(e.scale));
    });
    listen<KeyPressed>([](const KeyPressed& e) {
        if (e.key == Key::F6 && !e.repeat) notification::show("F6", "Event received");
    });
}
イベントフィールド内容
TickEventdelta_secondsホストの tick ごと
RenderEventcontexton_render の直後
KeyPressedkey, repeatGUI に消費されなかったキーの押下
KeyEventkey, down, repeatGUI に消費されなかったキー入力。旧 API
GameJoinedworld_identityワールドに入ったとき
GameLeftworld_identityワールドを出たとき
ScreenResizedwidth, height, scale初回 tick と、サイズや scale が変わったとき。単位は論理 DIP

タイマー

using namespace std::chrono_literals;

uint64_t timer_ = 0;

void on_enable() override {
    after(500ms, [] { notification::show("Ready", "Script enabled"); });
    timer_ = every(2s, [] { log::info("periodic"); });
}
  • after は 1 回、every は繰り返しです。どちらもタイマー ID を返し、失敗すると 0 を返します。
  • cancel_timer(id) で止めます。OFF やリロードでも自動で解放されます。
  • 発火はホストの tick です。止まっていた間の分をまとめて連続実行することはありません。

描画

on_render に渡される RenderContext で描きます。そのままだと単位は物理ピクセルです。logical() を通すと UI スケールに従う論理 DIP になるので、HUD はこちらを使うのがおすすめです。

void on_render(RenderContext& render) override {
    auto draw = render.logical();
    draw.fill_rounded_rect({24, 24, 200, 60}, 12, Color::rgba(20, 20, 24, 200));
    draw.text({40, 40}, "Hello", Color::white(), 20);
}
メソッド内容
logical()論理 DIP で描く RenderContext を返す
viewport_size()画面サイズ
center()画面中央
text(pos, message, color, size = 16)UTF-8 文字列
fill_circle(pos, radius, color)塗りつぶしの円
fill_rounded_rect(rect, radius, color)塗りつぶしの角丸矩形
stroke_rounded_rect(rect, radius, color, thickness = 1)角丸矩形の枠線
line(from, to, color, thickness = 1)線分
glass(rect, style)Liquid Glass のパネル

RenderContext はコールバックの間だけ有効です。メンバーに保存しないでください。座標や色に NaN、inf、範囲外の値を渡すと拒否されます。

Liquid Glass

BlockCount などの本体 UI と同じ Liquid Glass を描けます。

auto draw = render.logical();
draw.glass({24, 24, 300, 86}, Glass::regular().radius(24).refraction(.7F));
draw.text({44, 54}, "Medicon", Color::white(), 20);
指定対応
Glass::regular()対応
radius(value)対応。短辺の半分までに丸められます
refraction(0..1)対応。屈折と吸収の両方が変わります
opacity(0..1)対応
quality(GlassQuality::Inherit)対応。他の値は非対応
clear() / frosted() / prominent()非対応
blur / tint / saturation / highlight / border / shadow非対応

非対応の指定を使うと、診断が出て読みやすい GlassPlate 表示にフォールバックします。glass() は本物の Glass で描けたら true、フォールバックや拒否なら false を返します。

Windows の透明効果が OFF のときやハイコントラストのときも、Glass は止まって不透明なプレートになります。

UI パネル

on_ui ではボタンなどの操作できる UI を作れます。単位は論理 DIP です。

float progress_ = 0;

void on_ui(UIContext& ui) override {
    auto panel = ui.glass_panel("quick", {34, 380, 300, 160}, Glass::regular().radius(20));
    panel.label("Quick controls");
    if (panel.button("advance", "Advance")) progress_ = std::min(1.F, progress_ + .1F);
    panel.progress("progress", progress_);
}
  • on_ui が呼ばれるのは、ClickGUI が開いていてゲームにフォーカスがあり、Main Menu / Social / Disconnect / Splash が前面にない間です。
  • button はクリックかキー操作 1 回につき 1 度だけ true を返します。
  • パネルと widget の ID は固定してください。毎フレーム新しい ID を作ると上限で拒否されます。
  • Panel と UIContext は保存しないでください。関数を抜けるとパネルは自動で閉じます。
  • ClickGUI に重ならない位置に置いてください。

アニメーション

Tween<T> は float、double、Vec2、Color を補間します。

Tween<float> opacity_{0};

void on_enable() override {
    opacity_.to(1.F, std::chrono::milliseconds(260), Easing::OutCubic);
}

void on_render(RenderContext& render) override {
    render.logical().text({24, 24}, "Fade", Color{1, 1, 1, opacity_.value()}, 20);
}
  • Easing は Linear、OutCubic、OutExpo、InOutCubic です。
  • 途中で to を呼ぶと、現在値から続きます。
  • Windows のアニメーション効果が OFF のときは、すぐ目標値になります。

Storage

モジュールごとの文字列データを保存できます。

auto label = storage::get("label").value_or("Medicon");
storage::set("label", label);
  • get は読み込み済みのメモリから optional で返します。
  • set の true は「保存を予約できた」という意味です。ディスクへの書き込みは別スレッドで行います。
  • キーはファイルパスではありません。..、スラッシュ、バックスラッシュ、NUL は拒否されます。値は UTF-8 です。
  • on_disable の中からの set も保存されます。
Storage は暗号化されません。パスワードやトークンなどの秘密情報は保存しないでください。

ビルド

  • コンパイラは MSVC cl.exe(C++20、Windows x64、/MT)です。/sourceDependencies に対応した版が必要です。
  • LLVM-MinGW の clang++ も開発・テスト用に使えます。PATH にないときは MEDICON_SCRIPT_CXX にフルパスを設定します。clang-cl は非対応です。
  • Build / Reload は現在のソースを再評価し、Rebuild はキャッシュなしでビルドします。
  • エラーはファイル・行・列つきで Script Manager に出ます。コンパイラの出力は Cache/build/work-*/build.log に残ります。
  • ビルドに失敗しても、最後に動いていた版が動き続けます。

承認とリロード

スクリプトはゲームと同じ権限で動くネイティブコードです。サンドボックスではありません。信頼できるコードだけを承認してください。
  • 未承認の DLL は読み込まれません。DllMain も承認前には実行されません。
  • 承認はソースと DLL のハッシュの組に対して保存されます。コードが変わると再承認が必要です。
  • Revoke approval で承認を取り消すと、そのモジュールは解除されます。
  • リロードで新しい版の有効化に失敗すると、元の版に戻ります。
  • 外部 DLL や遅延ロード DLL に依存するスクリプトには対応していません。
  • 標準 C++ 例外は捕捉され、そのスクリプトだけが OFF になります。アクセス違反や無限ループは防げず、ゲームごと巻き込みます。
  • DLL 内で自作スレッドを動かし続ける設計には対応していません。

監査ログは Logs/script-manager.log に JSON Lines で記録されます。
